# All-at-Once 高命中的输入审计与 attention 判别缺口

现有证据更支持故障判别与信息表达的差距。实际请求没有带入根因答案或参考补丁，没有启用搜索或发生工具调用；attention 的候选覆盖较好，但候选内的正确性、首次错误承诺及恢复情况尚未被可靠区分。

## 输入、联网与评价是否有问题

核对三个历史 All-at-Once 套件，每套 102 条，共 306 份请求。使用各套件快照中的提示词和通用标注规则，仅以原任务、原轨迹允许字段、首个失败测试代码和错误信息重新构造输入，**306/306 与实际 messages 逐字一致**。将原始顶层 failure_id、failure_reason、gold_patch 等标注字段改成哨兵值，不影响重建输入。模型请求中的 failure_id/failure_reason 是输出格式说明，未填写样本答案。

| 检查 | Qwen3.8-Flash | 官方 DeepSeek Flash | MoMA DeepSeek-V4.1 |
| --- | ---: | ---: | ---: |
| 允许字段重建请求完全一致 | 102/102 | 102/102 | 102/102 |
| 启用搜索/工具的请求字段 | 0 | 0 | 0 |
| 返回中非空搜索/工具调用字段 | 0 | 0 | 0 |
| 根因解释全文/参考补丁全文混入 | 0/0 | 0/0 | 0/0 |
| 从模型返回独立核对的有效预测 | 83 | 98 | 95 |
| 从模型返回复算精确命中 | 48 | 57 | 56 |

Qwen 与官方 DeepSeek 的 204 份 SSE 最终文本已与保存 response JSON 逐条匹配，合法答案再用快照中的纯 JSON 解析函数核对 state 记录；因此 48/57 的命中确实来自模型返回。MoMA 使用历史响应 JSON 核对，其 102 个 function_call 字段均为 null，没有独立 SSE 原件，未将空字段计为工具调用。全部无效输出仍计入 102 分母。

Qwen 使用 Chat Completions；请求没有 enable_search，也没有 tools。其官方文档明确通过 enable_search:true 开启该接口的联网搜索：[阿里云联网搜索说明](https://help.aliyun.com/zh/model-studio/web-search)。DeepSeek 请求同样未提供外部工具，返回和 SSE 也无工具事件。原编码 agent 在轨迹里的历史命令、网页文本和 URL 是输入日志，不是诊断模型本次执行的搜索。

这项核验排查的是运行时答案泄漏、工具搜索和评价映射。公开问题是否曾进入基础模型的预训练数据，不能从本地请求证明；需要未公开的新任务、语义保持重命名以及缺陷位置/需求的成对变化来检查参数记忆。

## 为什么“进入 Top-5”不等于“能够选第一”

All-at-Once 读取了 102 条完整轨迹，每条都包含真正的根因步骤；Qwen 仍只答对 48 条，官方 DeepSeek 为 57 条。因此“看到根因就一定能定位”并不成立。当前 Top-5 衡量的是候选覆盖，未测量模型是否理解了哪个代码细节违反最终测试。

两个处理过程存在实质差异：

| 环节 | All-at-Once | 当前 attention 排序器 |
| --- | --- | --- |
| 直接判别对象 | 任务、完整轨迹原文、单独标出的最终失败测试 | 每步冻结语义向量、数值信号、已有图 |
| 表示 | 大模型联合读取原文 | MiniLM 254-token 分块编码、块向量按长度平均、384→128 固定投影，再经 32 维隐藏层 |
| 根因规则 | 明确区分错误计划/错误执行、错误承诺/探索、致命/非致命错误 | 标签提供最终根因位置；判别头未直接读取自然语言规则，q 仅保留标量及缺失标记 |
| 诊断过程 | Qwen/官方 DeepSeek 开启 thinking，最后选择一个最早根因 | 小型监督排序头；既有 q 来自关闭 thinking 的逐步批量评估 |
| 关系作用 | 在原文中比较谁违反约束、谁只是继承或恢复 | 汇总关联信息并与 local 直接相加 |

MiniLM 的官方定位是句段语义表示、聚类和语义搜索：[模型说明](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2)。它被用于这里的检索表示是合理的；现有实验尚未证明这样的压缩表示足以稳定处理 API 契约、否定条件、字符级差异与首次错误承诺。原文完整分块并不意味着所有判别细节都保留在最终一个向量里。上述能力差异目前尚未通过同一模型的受控对照分离，不能把全部差距单独归因于 thinking 开关。

## 新发现一：上游 q 判断经常没有给真根因有效支持

全部 102 条中，真根因有 **71 条最终 q=0、8 条缺失回退、23 条有有效正 q**。q=0 可由判为无错、uncertain、认为已恢复等规则产生；缺失后的 q=1 是中性回退，并非模型确认根因。

尤其在 Qwen All-at-Once 答对的 48 条里：**30 条根因的最终 q=0，3 条缺失，只有 15 条有有效正 q**。这直接定位到已有错误识别信号不足。q 模块也读任务和失败测试，但采用关闭 thinking、一次评估全部步骤的协议；它与 All-at-Once 的完整诊断不是相同的判断任务。

原 q 输出其实含 reason、evidence_ref、reference_ref、kind、recovered；进入 attention 时只保留转换后的 q 和是否缺失，违反哪条断言、证据来自何处以及恢复判断的解释均未直接传给排序头。这是可实施的信息补充点。

## 新发现二：最终失败目标与轨迹报错混合编码

`frozen_semantic.item_texts()` 将最终测试代码/报错与所有识别出的轨迹报错观察拼在同一个 failure 文本中，再分块平均。最终测试 token 占比中位数为 **3.77%**；102 条中有 **72 条低于 10%**、92 条低于 50%。总量为最终测试 99,891 tokens、轨迹报错观察 2,032,693 tokens。这是明确提供的最终测试字段占输入的比例，不是学到的 attention 权重；轨迹观察可能重复同一失败信息，因此也不等同于全部相关语义的占比。

Ansible 锁案例最终测试 649 tokens，轨迹报错 23,992 tokens，最终测试只占 2.63%。All-at-Once 将这个测试独立呈现，能直接对照 `__enter__` 断言和 `acquire/release` 实现。应把最终失败测试设为独立条件，轨迹中间错误留在各自步骤中。

针对这项假设，额外执行了一次固定 checkpoint 的离线干预：只编码最终失败测试，并同步替换 failure 向量与 decision×failure 特征，保留任务、步骤、q、图和全部权重。

| 设置 | Top-1 | Top-5 | MRR | 三种子命中 |
| --- | ---: | ---: | ---: | --- |
| 原混合 failure | 28.43% | 74.84% | 0.4741 | 27/28/32 |
| 仅最终失败测试 | 28.76% | 75.82% | 0.4766 | 27/29/32 |

仅增加 0.33 个百分点，组 bootstrap 95% 区间 −0.85 至 +1.31，组交换 p=1.0。输入组织问题确实存在，但单改该向量尚不能解释或解决主要 Top-1 差距；新表示仍需在训练阶段与判别目标一起检验。新模型推理 API 为 0，新增本地冻结编码不是新增训练。

## 关注范围与分数的作用：已有具体例子

Ansible 的 q 已明确识别第 5 步使用 acquire/release 而不调用上下文管理器，给出未恢复的错误证据；第 2 步编辑工具错误被标为已恢复，转换为 q=0。联合训练模型的 local 三种子均选对第 5 步，relation 却将第 2 步推至第一。上一轮把关系权重减半，两个种子恢复正确。这属于分数组合覆盖了已存在的正确判断。

Django 的前一步正确分析与后一步错误补丁，则在窗口和分数缩放后仍混淆；该例 q 输出缺失后全部回退为 1。OpenLibrary 的 q 将共享逻辑修改当作正确修复，未抓住 Booknotes 特殊需求被推广到 Bookshelves 的错误范围。它们更需要对照原文与测试约束做判断。

最近窗口试验：原版 28.43%，16 步窗口 29.08%，关系减半 28.76%；所有首位增量较小。窗口主要改变证据汇聚范围，无法自动补充上述错误语义判断。attention 权重高表示模型在汇聚该来源，不等于该步骤已经被验证为根因。

## 下一轮最有区分力的实验

先固定同一个 Qwen 模型、相同 thinking 配置与根因判定规则，比较：①完整原文 All-at-Once；②attention Top-5 的原文、局部前后文及相关长程证据，由同一模型裁决；③②再加入关系证据。候选来自折外预测，不能用真值补入根因；同时记录候选漏召回、候选内准确率、总 tokens 和延迟。

这组实验把“谁来判断是否有错”固定，才能看 attention 的候选筛选和关系组织是否有额外价值。另以相同全文提示词开/关 thinking 比较，单独测量推理配置贡献。监督版本则先分离最终失败条件，保留违反的约束/证据/恢复等信号，再在训练折内验证关系门控和正则。

当前最缺的是：**把候选步骤的具体行为与最终失败要求逐项核对，再区分首次引入、后续继承和真正恢复**。注意力可以组织这些证据，但我们还没有把这套判别稳定地落实到评分里。

审计复现：

```sh
.venv-attention-semantic/bin/python scripts/audit_all_at_once_inputs.py
.venv-attention-semantic/bin/python scripts/audit_failure_context.py
```

请求/输出审计保护 1749 份来源文件；失败条件干预保护 249 份来源文件，306 份原预测精确重放。新增 API 调用 0、训练 0。逐例结果位于 `outputs/attentionmap-aa-input-audit-20261027/`，原 baseline、模型与预测保持冻结。
