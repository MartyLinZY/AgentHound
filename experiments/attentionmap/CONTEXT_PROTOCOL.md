# 上下文组织端到端实验协议

2026-10-28，context_map_v1。运行分支 codex/attentionmap-context-20261028。

本轮问题：固定诊断模型后，调用图的上下文抽象能否帮助它读取原始轨迹并定位最早未纠正的关键错误？本轮固定一次上下文构建和一次诊断调用，不训练根因分类器。

## 冻结输入和方法

沿用 RootSE 102 条、35 个仓库/任务联合组。输入仅含任务、原始步骤允许字段、首个失败测试的代码和错误描述。根因标签独立保存，只用于最终评估。窗口、图和 map 不读取节点错误评分 q、旧预测或根因排序模型权重。

五组均使用 qwen3.8-flash、temperature=0、enable_thinking=true、max_tokens=32768，同一组诊断指令和原标注准则。返回有序的至多 5 个原始步骤 ID、首选解释及证据步骤。完整全文组重新运行，以保持本轮提示词和输出格式一致。每条轨迹每组一次调用；只重试网络/429/5xx，不按答案有效性或正确性重试。

| 组 | 上下文 |
|---|---|
| full | 完整允许字段，按原始时间展开 |
| window | 按失败/任务相关性选焦点及相邻 ±1 步，选中片段按时间排列 |
| graph | 沿原有依赖的双向阅读关系分配预算，显示原边及其阅读权重 |
| attention | 原边、局部邻接、路径/符号关联和语义关联组成 soft map，按阅读优先级展示并标记关联 |
| attention_flat | 与 attention 完全相同的原文片段，按时间平铺，去掉关系标记 |

同事实对照固定的是原始文本片段集合；关系标记和呈现顺序同时改变。因此该对照衡量组织方式这一组合的作用，不单独识别顺序或关系标记的效应。

## 表示和阅读分配

复用冻结 MiniLM 的 decision/action、observation、task 128 维表示；失败表示只含最终测试代码与错误。step 表示为归一化的 `0.6 decision + 0.4 observation`。query 为 `0.75 final_failure + 0.25 task`。单步阅读相关性 r 为归一化语义相似度和轨迹内 BM25 分数的等权和。

旧依赖可以双向阅读：执行方向仍保留为 earlier/later 标记，阅读后续结果不会改变执行先后关系。原图边权 1；相邻步骤 0.5；共享路径 0.8；至少两个低频符号关联 0.6；每行最多 4 个 cosine≥0.65 的语义邻居，权重 0.6×cosine。同一对关系取最大权重。路径和符号标记仅表达关联，不声称已验证因果或精确文件版本。

阅读矩阵 `A[i,j] ∝ W[i,j] × (0.25+r[j])`，按行归一化。孤立节点保留自环。阅读预算优先级使用 `p=0.55 seed+0.45 Aᵀp`，seed∝0.05+r，固定迭代 20 次。原图组使用同一规则但只保留原图关系。该优先级用于选择展开的上下文，不作为提交给评估器的根因答案。

## 上下文预算和原文

四个有界组统一 16,384 个 cl100k_base token 的轨迹视图上限，包含概览、原文、顺序/关系标记。这个 tokenizer 是统一预算代理；另记录 API 返回的实际输入、输出 token。所有组共用的任务、失败测试和诊断指令不计入轨迹视图预算，但计入请求实际成本。

有界组保留所有步骤的简短意图/操作概览。展开片段保留原始字段、步骤 ID 和字符位置。长字段由开头与查询相关的原文窗口组成，明确标记截取；所有有界组共用同一片段生成器。thought/response 各至多 384 token、action/observation 各 896、state 96、extra_info 64、execution_time 16。按阅读顺序尝试加入整个步骤包，并验证实际渲染后预算。attention_flat 复用 attention 的选中片段，节省的关系标记空间不再填入新事实。

full 保留完整文本并单列实际成本。它与预算组的比较属于完整阅读与预算阅读的比较；本轮不据此声称严格等总成本。

## 运行和验证

先按输入长度选择中位和最长两个案例作为技术 pilot，五组共 10 次，检查服务、格式与预算；不计算命中率来改参数。pilot 的原始请求与响应随后计入完整 510 个 case×method 任务，不重复请求。所有有界组 pilot 有效后启动全量。全文参照允许真实 context overflow 并保留失败记录。

准备阶段冻结源码、配置、102 条原始数据、已有图、向量、矩阵及 510 份实际消息；top-level 标注字段的哨兵替换必须不改变允许输入。每个片段必须逐字符等于原文，同事实组片段集合必须一致。缓存恢复核对请求哈希，未完成/格式失败记录不替换成旧预测。评估后核对历史文件哈希，并独立从响应重算排名与用量。

## 分析问题

主指标为全 102 条分母的 Top-1；次指标为 Top-5 和 MRR@5（未返回的根因计 0）。服务/格式失败按全分母计 0，同时报告有效输出率和有效样本条件指标。

预先指定 attention 对 graph、window、attention_flat、full 的四个配对比较。按 35 个仓库/任务组进行 cluster bootstrap 95% CI、组内整体交换的配对随机化检验，四项 p 值使用 Holm 校正。报告新增/丢失命中和效应量。每组本轮一次服务运行，区间反映案例组抽样而非独立模型重复运行波动。

机制分析：根因是否被展开、根因展开片段占原文比例、已展开时的定位率、同事实两组的分歧、具体因果与恢复证据是否保留。单步覆盖只能作为可观察指标；完整证据链是否被保留需要结合原文审阅。

成本分别报告新增诊断 API 请求与 token、离线构图时间、复用资产，以及原调用图的历史生成成本。当前实验证明的是缓存可用时的增量成本，从零运行应另加图构建和向量编码成本。

复现入口：`scripts/run_contextmap.py --stage prepare|pilot|run|all --api-key-file <现有密钥文件>`。推理环境使用 `.venv-attention-semantic`，新增依赖 tiktoken==0.12.0。
