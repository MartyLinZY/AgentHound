# v3：完整原文单元与关联阅读窗口

运行前协议，2026-10-29。

问题：固定诊断模型、图、优先级和总预算，优先保留完整决策单元，是否改善最早关键错误定位？在相同原文上，关联邻居的局部时间排列是否进一步改善？

三组：`v1_repeat` 原样重跑冻结 v1 attention 请求；`units` 完整单元、原关注顺序及关联提示；`units_window` 与 units 相同节点、原文片段和关联提示，将关联三元窗口内部按时间排序。各 102 条，同批随机交错，每格每条一次，pilot 按提示词长度选中位和最大案例，pilot 结果直接计入。

数据构建：只读取 v1 已冻结完整视图和 map。先还原每个步骤的白名单字段；保留原始字符偏移。若字段整体不超过单节点 2736 token 内容预算，视为一个完整单元；更大字段按空行段落、围栏代码块、diff hunk 分割。围栏、工具 JSON、diff hunk 保持完整；超预算的不可分单元跳过，不从中间截断。固定内容预算等于 v1 七字段预算之和（2736），优先 thought、response 完整字段，其后 action、observation，再 metadata。过大字段的单位按查询词重合降序、原始位置打破并列，展示时恢复原文字段顺序。记录每个被省略单元和原因。

节点选择沿用 v1 的关注排序与逐节点装入规则，overview、提示词和关联边均不变，总渲染内容上限 16384 cl100k 代理 token。片段改变可能改变选中节点，须报告根因展开率与完整决策覆盖，不能将整体差异全归因于边界变化。

窗口：从尚未分配的最高关注节点作锚点，在已选节点中分别找一个较早、较晚的关系邻居，按冻结 attention 取最大值。优先使用含非 adjacent_context 关系的邻居，无则使用相邻边；每窗最多 3 个节点，内部按原始时间，窗口间按锚点关注顺序。节点只展示一次。所有原文和每节点链接文字与 units 完全相同，不新增角色或因果标签。最后若窗口顺序导致分词预算超限，共同剔除最低优先节点，重新构建两组，确保同事实。该项只测试关系支持的局部时间组织。

模型、温度、thinking、输出上限、解析器和网络重试沿用 v1。无联网搜索工具；每次实际 payload 保存。失败保留且主统计按 102 条计 0，不依答案重试。参数在查看新答案前冻结；不根据本轮结果调参再替换结果。

主指标 Top-1，辅助 Top-5/MRR@5、早判/晚判、根因展开、完整 thought+response 覆盖和 provider token 用量。主比较 units−v1_repeat、units_window−units，第三项 units_window−v1_repeat 同族 Holm 校正。35 仓库/任务组 bootstrap 5000 次；组内交换两方法标签 20000 次，沿用既有实现与种子。完整有效交集另作敏感性分析。对历史 full/graph/window/attention 仅作背景对照，与 v1_repeat 的重复差异单列。

原始数据和标签不变，不排除困难案例。102 条曾用于开发，区间与 p 值用于开发判断；单次服务运行的随机性由本轮重复 v1 作描述，不能完整估计。
